# 예측 연구실 기획

## 목적과 사용자 질문

운영 서비스와 별개의 연구 환경에서 한국·미국 상장 주식 및 ETF의 방향 확률을 발행한 뒤, 나중에 관측한 시장 결과로 채점한다. 경험이 쌓일수록 처음 보는 상황에서 더 나은 확률을 제시하는지, 토론이 단일 모델보다 유리한지, 어떤 교훈이 오히려 과신을 유발하는지 확인한다. 매수·관망·매도 여부와 무관하게 적격 종목은 동일한 규칙으로 관측한다. 기존 가상매매의 손익과 새 예측 평가는 목적과 측정 단위가 다르다.

## 사용자 경험

홈에서 연구 대상, 최근 발행 사례, 만기 대기, 채점 완료, 미발행·실패를 구분한다. 확률과 판단 근거를 사례별로 열람하며 방법별 비교는 공통으로 채점된 동일 사례에서 수행한다. 사용자에게 Brier 점수와 개선량의 방향, 표본 수, 반복되는 종목·관측 창의 한계를 설명한다. 표본이 없는 화면에 0% 성과를 표시하지 않는다. 모의 데이터는 운영 연구 성적에 합산하지 않는다.

## 실험 질문

1. 최근 같은 종목의 관측 빈도만 활용하는 기준선 대비 단일 확률 예측은 더 정확한가?
2. 같은 근거로 기존 토론 노드들이 도출한 예측은 단일 모델보다 나은가?
3. 시장 근거와 모델을 고정하고 성숙한 기억 하나만 제공했을 때, 독립된 단일 모델 응답의 Brier 점수는 어떻게 변하는가? 한 번의 차이에는 모델 자체 변동도 포함된다.
4. 이 효과가 특정 종목·기간에 집중되는가? 비교에는 모델·규칙 버전과 공통 표본 수를 표시하고 새 기간을 전향적으로 관측한다. 점수에 따라 실거래, 프롬프트 또는 모델을 자동 승격하지 않는다.

예를 들어 같은 날의 예측에서 기억을 보지 않은 모델이 상승 확률 50%, 기억을 본 모델이 70%를 발행했다고 하자. 실제 상승하면 두 Brier 점수는 0.25와 0.09로, 그 기억을 사용한 쪽이 0.16점 개선된다. 반대로 보합 또는 하락하면 0.25와 0.49로 0.24점 악화된다. 검색 시 이 차이와 실제 비교 횟수를 함께 쓰며, 인용 횟수만으로는 가점이 생기지 않는다.

## 범위 및 인수

새 Windows Git 브랜치, 전용 PostgreSQL, 별도 스케줄러와 로컬 웹 앱을 사용한다. 초기 관찰 목록은 기존 예약 설정의 공개 티커에서 지원 종목만 복사한다. 구독 인증은 Windows 사용자 프로필의 공식 Codex 런타임을 이용한다. 새로운 사례 저장 → 기한 판정 → 가격 근거와 채점 저장 → 기억 생성 → 후속 사례에서 기억을 하나 선택 → 독립 예측 쌍 비교 → 화면 조회가 이어져야 한다. 테스트에는 독립 DB와 고정 시계·가격을 쓰고, 새 연구 DB에는 실제 발행만 남긴다. 실제 개선 여부는 여러 미래 시장 구간의 결과로 판단한다.
