# 예측 연구실 설계 및 인수 기록

상위 요구사항은 [기획](PRODUCT.md)을 따른다. 세션 재개 시 두 문서를 먼저 읽고 코드·테스트·실행 결과와 대조한다. 계약이나 범위를 변경할 때 이유와 검증 결과를 이 파일에 반영한다.

## 전향 실험 공통 규약

- 대상은 한국·미국 상장 주식·ETF다. 실제 관찰을 마친 최신 거래일의 지역 거래소 달력·마감 시각을 확인한다. 한 종목·거래일·실험 버전에 사례 하나를 만들고 OHLCV 근거, 출처, 시각, 대상 세션을 동결한다. 예정 진입은 그 데이터 세션 다음 거래일 시가, 종료는 진입일을 포함한 다섯 번째 세션 종가다. 예측 발행은 진입장 개장 전까지만 허용한다. 주말·휴장·시간대·서머타임은 거래소 달력 기준이다.
- 모든 방법은 동일한 시점에 저장한 동일 입력에서 출발한다. 제어군에는 기억이나 다른 방법의 출력이 들어가지 않는다. 시장 데이터 이후의 뉴스·시세를 추가 조회하거나, 미체결·관망 때문에 표본을 버리지 않는다. 배당·비용 제외 가격 방향을 사용한다. 창에서 분할·부실 시세가 확인되면 평가에서 보류 또는 사유와 함께 제외한다.
- 기본 방법은 `baseline`, `single`, `debate`, `memory`다. 섹터 검색을 도입한 뒤 새로 관측한 사례에는 아래 조건에 따라 `memory_sector`를 추가한다. 기준선은 과거에 이미 끝난 동일 5세션 창의 상승률에 Laplace 보정을 적용한다. 단일 모델은 확률과 검증 가능한 근거를 낸다. 토론 방식은 기존 강세·약세·심판 노드에 동결된 근거를 주는 통제 버전이다. 입력 접근 조건이 다른 운영 12에이전트의 전체 성과로 해석하지 않는다. 기억 방법은 single과 같은 모델·프롬프트의 독립 실행에 해당 사례 이전에 관측·저장된 교훈 하나를 더한다. 기억이 없으면 건너뛴다. 각 방법의 모델·프롬프트/방법 버전, 확률, 근거, 발행 시각, 사용한 기억을 보존한다.
- 사례별 Brier = (p−y)², 종가가 진입 시가보다 높으면 y=1, 나머지는 0. 낮을수록 좋다. 비교는 동일 두 방법이 모두 성공·발행한 동일 사례에 한정한다. 기준선 대비 개선과 single 대비 memory 개선은 통제 점수에서 처리 점수를 뺀 값으로 양수가 개선이다. 평균 점수, 공통 건수, 미성숙·불완전 사례를 구분한다.
- 미래가 관측된 single 예측에서만 근거·확률·실제 결과·시장 특징을 가진 기억을 만든다. 정확·오류 양쪽을 남긴다. 유사한 특징·종목/시장과 관측 근거를 이용해 이후 사례용 기억을 고르고, 기억을 쓴 실제 paired Brier 차이를 추적한다. 미래·자기 사례·레거시 텍스트를 선택하지 않는다. 초기에는 PostgreSQL의 구조화된 경험 검색을 사용해 기존 Chroma와 완전히 분리한다. 점수는 가상 P/L과 분리한다.
- 한 방법의 실패는 다른 방법을 폐기하지 않는다. 반복 실행과 동시 워커는 발행·채점·교훈을 중복 생성하지 않는다. 기한을 넘긴 과거 예측을 나중에 완성하지 않는다. 신규 연구 DB의 리포트는 전향 관측만 허용한다. 상태·실패 사유와 버전이 보이는 화면을 제공한다.

## 경계와 실행

### 시장·섹터를 이용한 기억 검색 실험

새로 관측하는 사례에 `retrieval_policy=sector-v1`과 버전 있는 `classification`을 동결한다. 한국·미국 시장과 기존 가격·만기 실험 버전을 유지하며 이미 발행한 사례에 분류나 예측을 소급해서 덧붙이지 않는다. 기업은 주식 섹터·업종, ETF는 기초자산 유형·노출로 분류한다. 알 수 없는 분류는 종목 간 전이에 사용하지 않는다. 분류는 검색용이며 단일 모델과 기존 기억 비교군의 시장 입력에는 추가하지 않는다.

기존 `memory` 선택 규칙을 비교군으로 유지한다. 추가 `memory_sector`는 같은 시장에서 예측 시점 이전에 성숙한 기억만 사용한다. 같은 종목의 경험과 가격 상태가 가까운 동종 후보를 함께 검토한다. 다른 주식의 교훈을 쓰려면 과거 사례의 같은 데이터 세션에 독립적인 동종 종목에서도 유사한 시장 대비 움직임이 관측되어야 한다. 이 확인에는 목표 예측 시점 이전에 동결된 가격 특징만 사용한다. 이는 가격 흐름의 확인이며 개별 회사 사건의 원인을 입증하지 않는다. ETF 간 전이는 같은 기초자산 노출에서만 허용한다. 분류 일치는 후보 선정에 사용하며 교훈의 성과 점수를 올리지 않는다.

두 방식이 같은 기억을 고르면 추가 모델 호출을 생략하고 그 사실을 기록한다. 다른 기억을 고르면 같은 모델·프롬프트·목표 시세로 예측을 별도 발행한다. 같은 사례에서 두 예측이 모두 발행되고 만기 결과가 있을 때 기존 검색의 Brier에서 새 검색의 Brier를 뺀다. 비교 표본·동일 선택·적격 기억 부재를 구별하고, 열린 사례의 검색 근거와 성과 화면에서 결과를 확인한다.

기업 고유의 만기 급변을 업종 교훈으로 재사용할 위험도 확인한다. 다른 주식에서 빌릴 때는 원본과 확인 종목이 같은 과거 진입·만기 구간에 채점되었고, 두 결과가 모두 목표 예측 전에 기록되었어야 한다. 원본·확인 종목의 5거래일 실현 수익률은 같은 방향이어야 하며, 두 수익률 격차는 각각의 사전 20거래일 일별 변동성 중 작은 값의 √5배 이내여야 한다. 임계값은 사전에 정한 검색 규칙으로 버전을 관리한다. 새 방식은 유사한 후보 중 기억을 사용한 뒤의 Brier 개선·악화로 우선순위를 조정하고, 서로 겹치는 관측 창은 중복 가산하지 않는다.

한국의 기존 v2 사례 8개에서는 KODEX 200 기준 시세의 기업행위·결측 검사로 시장 대비 수익률을 구할 수 없었다. 원본과 확인 종목 양쪽에 공통 시장 기준이 있으면 이를 사용한다. 부족하면 그 과거 세션에 이미 관측한 다른 섹터 주식들의 20거래일 수익률 중앙값을 두 종목의 공통 기준으로 삼는다. 같은 시장·가격 실험 버전에서 평가 섹터를 제외한 최소 2개 섹터, 3개 종목이 필요하다. 이 보조 기준은 기억 검색에만 사용하고 화면에서 기준의 종류와 구성 종목 수를 밝힌다.

초기 규칙은 원본과 확인 종목이 공통 기준보다 같은 방향으로 각각 1.5%p 이상 움직였는지 검사한다. 두 상대수익률 격차는 3%p와 원본 상대수익률 절댓값의 절반 중 작은 값까지 허용한다. 세부 업종이 다르거나 미상일 때는 절반을 25%로 줄이고 목표와 원본 간 가격 특징의 허용 차이도 절반으로 줄인다. 최종 후보의 경험 점수는 사용 후 동일 모델 단독 예측 대비 Brier 개선량의 합을 독립적인 사용 횟수 + 5로 나눠 계산한다. 정확한 거리 척도와 숫자는 [선택 규칙](../../packages/tradingagents/forecast_lab/sector_retrieval.py)에 둔다.

2026-11-24 인수에서는 운영에 동결돼 있던 가격으로 과거 20거래일 특징과 뒤 5거래일 결과를 검증 DB에서 재구성했다. 10월 29일 코카콜라 입력에 대해 기존 방식은 코카콜라, 새 방식은 월마트의 다른 기억을 골랐다. Windows 구독 모델로 두 예측을 발행하고 같은 시장 입력 해시, 서로 다른 기억 ID, 만기 결과 및 Brier 차이를 확인했다. 한국은 10월 28일 두산에너빌리티 사례에서 한화에어로스페이스 기억을 선택했고, 다른 섹터 4종목의 중앙값과 두 주식의 과거 5거래일 결과로 근거를 확인했다. 한국 재생에는 고정 응답 모델을 사용했다. 이 인수 자료는 운영 통계에서 제외한다.

기존 DB 제약을 확장하는 마이그레이션을 포함한 자동 검사 112개가 통과했다. Windows 배포 전후 기존 운영 사례 23개의 스냅샷·방법 기록 92개·현재 결과·기억·외부 비교 자료를 해시로 대조했다. 새 규칙은 이후 관측부터 적용되며 배포 시점의 실제 비교 표본은 0쌍이다.

### 연구·가상매매 화면의 시각 설계

이 브랜치의 사용자 작업 공간은 **Forecast Lab** 한 제품으로 표시한다. 데스크톱은 짙은 남색의 고정 탐색과 밝은 데이터 화면, 모바일은 현재 위치와 전체 메뉴를 제공한다. 공통 바탕은 `#F4F6FA`, 패널은 흰색, 본문은 `#17243B`, 주된 선택·행동은 `#305CE0`를 사용한다. 숫자는 자릿수를 맞추고 상태는 색과 텍스트를 함께 사용한다. 연구·콘솔 모두 같은 글자·간격·패널·포커스 규칙을 따른다.

연구 첫 화면은 최근 예측과 선택한 종목의 실제 확률·동결 시세부터 읽게 하고, 채점 성과는 별도 보기로 제공한다. 데이터가 없는 기간에는 이유를 표시한다. 콘솔은 모드·통화·인증 흐름을 보존하면서 대시보드와 포트폴리오·예약·리포트에서 가장 자주 수행하는 작업을 먼저 배치한다. 배포 전 실제 자료로 데스크톱·모바일 화면, 필터·사례 선택, 리포트 본문과 주요 경로를 확인한다.

| 화면 | 설계 및 검증 |
|---|---|
| 예측 사례 | 종가 차트는 선택한 사례에 동결된 가격만 사용한다. 전체 기간과 최근 20개 관측값을 전환할 수 있다. 확률은 실제 발행값을 표시하고, 보류한 방법은 상태를 표시한다. 11월 23일 FSLR의 종가 65개, 마지막 종가 $146.53, 기준선·단일·토론 36.5%·39.0%·48.0%를 저장값과 대조했다. |
| 리포트와 대시보드 | 운영 대시보드에서 최근 발행 리포트로 바로 이동한다. 목록은 발행순으로 정렬하고 종목명이나 티커로 검색한다. 상세 첫 화면에 최종 판단을 펼치고, 분석 단계별 근거와 회차 선택을 제공한다. KO와 WMT의 본문 패널 13개씩을 모두 펼쳐 한국어 강조와 내부 키 노출 여부를 확인했다. |
| 포트폴리오 | 가상계좌가 없는 경우 초기 자본·통화 설정 버튼을 제공한다. 버튼을 누를 때 설정 창을 열고, 관리자 인증을 거치면 입력하던 값으로 돌아온다. |
| 탐색 | 901px 이상에서는 왼쪽에 탐색 메뉴를 고정하고 좁은 화면에서는 전체 메뉴 버튼을 제공한다. 모바일 메뉴는 Escape로 닫을 수 있으며, 이동하면 초점이 새 화면으로 옮겨간다. 데스크톱·모바일 브라우저에서 연구·리포트·포트폴리오·운영 경로를 확인했다. |

### 콘솔 화면별 정보 구조와 모바일 인수 기준

회고 요청의 선택 단위는 현재 종목에 속한 포지션이다. 종목을 바꾸거나 선택 창을 닫은 뒤 도착한 응답은 이전 선택을 복원할 수 없다. 종목 상세의 최신 AI 분석과 과거 분석도 리포트 상세와 같은 판단 구분을 따른다.

연구 상태·통계·사례 목록은 각자 조회 결과와 오류를 표시한다. 통계 장애 중에도 목록에서 사례를 열 수 있어야 한다. 주기 갱신에서는 선택한 사례에 새 발행·채점 등 변화가 생겼을 때 상세 근거를 갱신한다. 예약과 리포트 목록은 종목별 최신 기록을 목록 조회에 포함해 종목 수에 따라 요청 횟수가 늘어나지 않게 한다.

2026-11-24 Windows 배포에서 코카콜라 응답을 월마트보다 늦춰 월마트 포지션만 제출되는지 확인했다. 동일한 자료에서 리포트 상세, 최신 분석, 분석 이력 모두 분석 매도와 실행 제안 관망을 표시했다. 격리 브라우저에서 통계 응답만 실패시키자 사례 20건과 상세 전환이 계속 동작했고 다음 정상 응답에서 통계가 복구됐다. 실제 사례 23번의 첫 상세 응답은 34,512바이트였고 같은 ETag를 보낸 재조회는 본문 없는 304였다. 배포 전후 예약 24개와 리포트 요약 14개를 대조했고 예약 화면의 개별 회차 요청은 24회에서 0회로 줄었다.

거래를 검토하는 사람의 질문을 기준으로 화면을 구성한다. 보유 종목은 현재·종료 거래의 수와 목록에서 상세로 이어지고, 매매 검증과 회고 분석은 평가 대상과 결과·교훈을 구별해 보여준다. 비어 있는 목록에는 기록이 만들어지는 시점과 이어서 확인할 수 있는 화면을 제공한다. 실행·예약 상세는 상태, 시각, 단계별 기록 순서로 읽게 한다. 서비스 소개는 현재 전향 연구의 목표, 동결 시세·확률 발행·5거래일 후 채점·성숙한 기억 재사용, 가상매매 두 모드의 역할을 실제 화면으로 연결한다.

한국어 콘솔의 매매 판단은 매수에 적색, 매도에 청색, 관망에 황갈색을 사용하고 한국어 레이블을 유지한다. 미기록에는 별도의 중립 표시를 사용한다. 매매 판단과 손익·실행 상태를 각각의 맥락에서 표시한다. 짧은 필터 이름과 배지는 한 줄에서 중앙에 맞추고, 목록의 머리글·본문은 동일한 열을 사용한다. 작은 화면에서는 관련 필드를 한 묶음으로 재배치한다. 모바일 인수 때는 가로 넘침뿐 아니라 실제 글자의 줄 수, 숫자와 레이블의 높이, 긴 종목명, 빈 목록·데이터가 있는 목록과 상세를 함께 확인한다.

리포트 목록과 대시보드의 최근 판단은 분석 결과를 가리킨다. 상세에서는 분석 판단과 실행 에이전트가 제안한 방향·수량을 별도로 표시한다. 체결 내역은 거래 기록을 사용한다. 모바일 리포트 행은 위에 종목과 판단, 아래에 건수와 발행 일시를 배치한다. 보유·종료 기록은 계좌와 표시 통화에 따라 구분하고, 매매 검증은 종료된 거래와 작성된 교훈을 보여준다. 각 화면에는 결과를 바꾸는 필터만 표시한다.

개편 전에는 페이지 가로 넘침이 0인 393px Chrome에서도 ‘전체’와 ‘이전 투자 0’이 각각 두 줄이었다. 인수에는 글자 범위의 실제 좌표를 검사하는 [레이아웃 회귀 검사](../../scripts/check-forecast-review-layout.py)를 사용한다. 소개·예약·보유·리포트 제목의 왼쪽 위치는 393px에서 모두 14px, 1440px에서 모두 256px로 일치했다. 운영 조회 시점의 리포트 판단은 관망과 매도였으며, 매수·미기록과 긴 한글 종목명은 격리된 브라우저 응답으로 검증했다.

### 통합 화면 개정

종목을 식별하는 제목·목록·상태·상세 탐색은 회사명 또는 펀드명을 주 정보로, 거래소 티커를 작은 보조 정보로 표시한다. 연구 단독 화면에서도 기본 관찰 종목과 시장 기준 종목의 이름을 읽을 수 있어야 한다. 통합 앱은 등록된 표시 이름을 활용하며 이름이 없는 종목은 티커 한 번으로 식별한다. 검색은 이름·티커를 모두 지원하는 기존 동작을 유지하고, 경로·API·저장된 리포트 원문과 연구 스냅샷은 원래 식별자를 사용한다.

브라우저 진입점 8014에 기존 Svelte 콘솔과 연구 탭을 통합한다. 콘솔은 같은 출처의 전용 경로에서 기존 FastAPI REST 및 WebSocket을 사용한다. 연구 PostgreSQL 클러스터 안에 가상매매 전용 DB를 별도로 두고 전향 사례 DB의 스코어·기억과 분리한다. 콘솔의 등록·분석·포트폴리오 변경은 이 전용 환경에서 수행한다. 운영 DB와 공개 사이트는 각자의 배포 설정을 사용한다. 인수 검증에는 두 모드, 각 주요 화면·상세 경로, 인증·실시간 연결, 실제 토론 근거의 Markdown 렌더링과 구조화된 데이터 표시를 포함한다.

기존 리포트에서는 수치 다음에 한국어 조사가 이어지는 강조도 확인했다. KO와 WMT의 본문 패널을 각각 13개 모두 펼쳤을 때 KO의 **32.0%→33.4%** 및 **48%**, WMT의 **49%**가 강조 요소로 표시됐다. 이 화면의 본문에 Markdown 별표, JSON 코드 펜스, 전략 객체의 내부 키가 남지 않았다.

저장소 및 통계는 `packages/tradingagents/forecast_lab/store.py`, 시장 수집 및 예측은 같은 폴더의 `engine.py`, 앱·스케줄·화면은 별도 연구실 엔트리포인트에서 관리한다. 고정 역할은 기존 코드베이스와 공식 인증 클라이언트를 재사용한다. 연구 프로세스는 운영 DB·포트·벡터·큐·파일 캐시에 의존하지 않는다. Windows의 별도 PostgreSQL 인스턴스와 루프백 웹 서버에서 운용한다. 외부 터널의 기존 서비스는 그대로 유지한다.

## 개발 및 검증 순서

### 첫 구현에서 확정한 결정

- 토론 기준은 원본의 투자 토론(강세·약세·연구심판)부터 트레이더, 세 위험 분석가, 최종 위험심판까지 여덟 개 후단 노드를 사용한다. 원본의 외부 조회 분석가 대신 관측 직후 동결한 종목·시장 근거를 제공한다. 같은 자료에서 추론 방식의 차이를 비교하기 위한 결정이다. 시장 근거에는 미국 SPY 또는 한국 KODEX 200 ETF(069500.KS)의 같은 기간 정보와 상대 흐름을 포함하며, 누락 여부를 기록한다.
- 위험관리 참고값은 사전에 정한 동일 정책으로 계산한다. 확률이 0.5를 넘을 때 자본 1단위를 매수하고 그 외에는 현금으로 두며, 다섯 번째 종가까지의 비용 차감 전 수익률을 비교한다. 공매도, 거래비용, 종목 간 자금 배분은 모델링하지 않는다. 예측 순위는 Brier로 산출한다.
- 연구실은 기존 서비스의 로그인·재시작 주기와 별개로 실행한다. 연구 앱이 상시 동작할 영구 체크아웃은 `C:/Users/samda/dev/TradingAgents-ForecastLab`, 브랜치는 `codex/forecast-lab`이다. 신규 PostgreSQL 17 클러스터의 루프백 포트는 55434이며, `forecast_lab_research`는 전향 연구, `forecast_lab_acceptance`는 검증 전용이다. 서비스 주소는 `http://127.0.0.1:8014/`다. 구성 및 데이터는 `%LOCALAPPDATA%/TradingAgentsForecastLab`에 둔다.
- 경험 검색은 같은 시장·실험 버전에서 같은 티커를 우선한다. 비교 가능한 수치 특징의 거리로 가까운 후보를 정하고, 최소 거리와의 차이 0.05 이내에서 누적 유용성을 적용한다. 과거에 그 기억을 제공했던 후속 사례의 동일 모델·프롬프트 계열에서 single Brier − memory Brier를 구한다. 같은 종목의 겹치는 결과 창은 종료가 빠른 창부터 하나씩 남긴다. 그 합을 (표본 수 + 5)로 나눠 표본이 작을 때 중립으로 수축한다. 현재 관측 이전에 양쪽 발행과 실제 결과까지 알려진 표본만 사용한다. 개별 교훈의 효과에는 독립 모델 응답의 변동이 포함된다.
- 확률 보정은 20% 폭 구간별 평균 예측 확률과 실제 상승 빈도, 표본 수로 점검한다. 비교에는 종목 수와 관측일 수도 함께 남긴다. 여러 종목이 같은 시장 충격을 공유하고 5세션 창이 겹치므로 행 수를 독립 실험 수로 취급하지 않는다.
- 2026-11-23 한국 거래일의 마감 후 Yahoo 일봉을 조회했을 때 당일 시가 0·종가 누락이 관측되었다. 한국은 NAVER 일봉을 입력과 결과 양쪽에 일관되게 사용하고 Yahoo 종목 식별·시장·기업행위 근거를 검증한다. 출처가 불분명하거나 분할 등으로 가격 기준이 달라질 수 있는 경우의 처리는 엔진 테스트와 함께 확인한다. 미국 주식·ETF의 일봉 출처는 Yahoo다.
- 통제 토론 외에 기존 서비스가 **실제 발행한** 확률도 별도 관측표에 담을 수 있다. `FORECAST_LAB_LEGACY_REFERENCE=1`이면 연구실이 루프백 운영 리포트 GET으로 발행 시각·모델·시장 데이터 날짜·목표 창을 확인한다. 기존 규칙은 발행 현지 날짜가 지난 첫 거래일을 사용하므로, 연구실의 목표 창과 일치하고 진입 시가 전에 확보한 경우에만 보관한다. 지연 수집이나 만기 뒤 맞춰 넣기는 허용하지 않는다. 원본은 분석 도구와 입력이 더 많아 이 비교는 같은 시장 결과를 본 관찰 비교다. 기준선·단일·토론·기억의 통제 실험과 성과를 따로 표시한다. 기존 서비스가 정지해도 연구 경로는 독립적으로 작동한다.
- 향후 비교 기간은 시장 현지 데이터 세션을 기준으로 한 달력 월로 정한다. 매월 종료 후 이미 발행했던 모델·규칙끼리 공통 표본에서 비교한다. 그 결과를 바탕으로 바꾼 규칙은 새 버전으로 표시하고 다음 기간에서 평가한다. 앞선 기간의 개선을 같은 기간에 다시 검증한 성과로 집계하지 않는다. 열람용 날짜 필터와 원래의 고정 발행 기록을 보존한다.

1. DB 스키마, 원자적 저장·채점·기억 검색 및 공통 표본 지표.
2. 거래소 기준 스냅샷·예측 방법·만기 가격 검증.
3. 별도 스케줄 및 API, 한국어 연구 대시보드와 검증 도구.
4. 전용 DB에서 신규 실행, 독립 테스트 DB에서 시간 경과·중복·비교·기억 재사용 검증, 브라우저 점검.
5. 실제 실행 위치와 명령, 결과와 남아 있는 관측 조건을 아래에 인계한다.

## 실험 버전과 첫 인수 기록

- `direction-5s-v1`으로 SK하이닉스와 현대차 두 건을 실제 발행했다. 한국 과거 OHLC 차트는 배당 전후의 조정 기준을 일관되게 확정하기 어려워 후속 규칙을 `direction-5s-v2`로 등록했다. v2는 해당 구간을 가격 특징·빈도 기준선과 만기 검증에서 검사한다. 같은 문제가 벤치마크에만 있으면 시장 상대 특징을 자료 부족으로 표시하고 종목 예측은 계속한다. 입력 출처와 거래소 달력 버전을 사례에 기록한다. 두 초기 사례의 발행 기록은 보존하고, 방법별 비교와 기억 검색은 같은 실험 버전 안에서 수행한다.
- v2 실제 사례인 삼성전자(005930.KS)의 관측 기준일은 2026-11-23이다. 검증된 과거 창 56개 중 23개가 상승해 기준선은 24/58(41.38%)이었다. 같은 입력으로 단일 모델과 여덟 역할 토론이 각각 개장 전 확률과 근거를 발행했다. 이 시점에 사용할 성숙한 경험은 0건이었다. 목표는 11월 24일 09:00 시가부터 11월 30일 15:30 종가까지다. 첫 한국 결과 수집은 11월 30일 15:50 KST부터 가격 검증을 거쳐 가능하다.
- 전용 PostgreSQL을 포함한 전체 자동 테스트 87개를 통과했다. 격리 DB에서는 만기 전후 시계를 이동해 실제 결과 저장, 사례 기반 기억 생성, 뒤의 예측에서 재사용, 같은 사례의 확률 점수 비교, 중복 실행과 장애 후 재개까지 검증했다. Windows Codex 구독 인증으로 실제 모델 호출을 확인했다. 연구 DB에서는 당시 발행 가능했던 사례만 누적한다.
- 연구 DB에 저장한 삼성전자 사례를 Chrome의 데스크톱(1440px)과 모바일(390px) 너비에서 열어 개별 확률·근거·만기와 시장 필터를 확인했다. 실제 백업을 새 임시 DB에 복원해 관찰 종목 23개와 해당 시점의 사례 4건·방법 기록 14개를 확인했다. 이후 쌓인 사례 수와 단계별 현재 상태는 대시보드와 [운영 문서](OPERATIONS.md)에서 확인한다.

### 첫 전체 스캔

11월 23일 한국 장 마감 이후 등록한 23개 티커를 모두 확인했다. 현행 v2에서는 한국 8종목에 기준선·단일·토론 확률 24개를 발행했다. 한국 267260.KS와 316140.KS에는 각각 11월 10일과 9일의 배당 표시가 있어 21세션 입력 검증에서 보류했다. 미국 13종목은 첫 스캔 시점에 이미 해당 거래일의 장이 열려 있었다. 이 티커들도 다음 발행 시간대의 관찰 목록에 남는다. 24개 발행의 실제 결과와 사용 가능한 성숙한 기억은 이때 각각 0건이었다.

초기 v1을 포함한 실제 확률 30개 모두 동결 시각 이후, 진입장 개장 전에 발행되었으며 각 사례 안에서 방법별 시장 입력 해시가 일치했다. Windows 작업 스케줄러로 연구 앱을 재기동해 30개의 사례·방법·확률·발행 시각·시장 입력 해시가 전부 보존됐음을 확인했다. 같은 기간의 v1과 v2 중복 티커는 독립 시장 표본으로 합산하지 않는다.
