기준 태그는 `gant-v1`과 `research-v2`다. 이후 브랜치가 이동해도 이 태그에서 분기 당시 코드를 복원할 수 있다.

목표는 주가 방향 판단을 발행 시점 자료로 재현하고, 만기가 지난 뒤 어떤 근거와 기억이 도움이 되었는지 확인하는 것이다. 운영에서는 v2 한 곳에서 분석과 가상매매를 예약·실행한다. v3는 독립 Windows 체크아웃에서 같은 결과를 읽고, 종목·시각이 맞는 보조 출처를 표시한다. 최초 v3 실험의 PostgreSQL 클러스터에는 당시 기록과 출처가 보존되어 있다.

## 기획과 구현의 순서

구현 전에 기획과 검증 계약을 기록한다. 담당자가 나뉘어 구현하고, 실제로 달라진 계약·검증 결과·재시작 방법은 같은 변경에서 갱신한다. 개발 세션의 기억은 사용자 환경에 보관하고 시장 판단에 쓰이는 운영 학습 표본은 v2에서 전향적으로 수집한다.

## 검증 계약

1. 발행 시 가격 스냅숏에서 측정 가능한 가설과 재검토 조건을 동결한다. 어떤 기준 시세·날짜·통화를 썼는지 표시한다. 조건의 성립 여부는 발행 후 실제 관측값으로만 평가하며 자료가 없으면 평가 대기로 구별한다. 조건 평가가 다섯 거래일 상승 확률·Brier 점수·동일 사례 기억 비교의 정답을 바꾸지 않는다.
2. 최근 30일 이슈를 수집하는 제품 작업은 전용 수집 명령에서 실행한다. 출처·제목·공개 시각·최초 관측 시각을 저장하며 두 시각이 모두 예측 시점 이전인 근거만 조회한다. 수집 장애, 출처 없음, 시장 인과관계 미확인은 그대로 드러낸다. 초기 릴리스에서는 이슈를 별도 근거로 열람하고 확률 입력 변경은 독립적인 실험으로 검증한다.
3. 예측 연구 화면에서는 회사명과 발행 확률, 관측 기간, 검증 결과를 먼저 읽는다. 선택한 사례에서 당시 가격, 조건, 시점이 맞는 시장 이슈와 출처, 방법별 확률을 조사할 수 있어야 한다. 모바일 및 공개 조회에서 동작하고, 빈 표본에는 실제 상태를 표시한다.
4. Impeccable과 claude-mem은 개발자 도구로 운영한다. last30days의 개발자용 검색과 서비스 수집의 설치·데이터·실행 지점을 분리한다. 외부 레포를 통째로 제품에 포함하지 않는다. 주가 예측력 개선은 만기가 지난 공통 사례에 대한 전향 비교로만 평가한다.

### 예약 실행 시 최근 30일 출처 수집

v2가 종목의 새 연구 스냅숏을 확정하거나 예약된 가상매매 분석을 실행할 때 같은 종목의 last30days 검색을 호출한다. 최초 관측 시각은 v3 아카이브에 실제 결과를 저장한 시각이다. 이후 만들어진 예측 사례와 매매 리포트만 해당 결과를 보조 출처로 읽는다. 시세 검증에서 탈락한 실행, 이미 동결된 사례의 재시도, 거래 대기열 점검만으로 검색을 반복하지 않는다.

두 분석이 같은 종목을 처리하면 최근 성공 또는 정상 빈 검색을 6시간 공유한다. 중복 실행은 DB에서 조정하고, 장애는 실패로 기록해 짧은 재시도 간격을 둔다. 수집을 기다리는 시간에는 상한을 둬 분석과 매매 예약이 계속 진행되게 한다. 운영에는 검색 요청을 만드는 스케줄러가 v2에 하나만 있다. 자료는 조회·검증용이며 기존 모델 입력과 점수 계약을 유지한다.

## 통합 콘솔

종목별 예측을 읽는 기본 단위는 사례다. 사례를 열면 발행 전 가격 차트, 해당 시점까지 읽을 수 있던 30일 출처, 방법별 판단, 만기 관측과 기억이 같은 페이지에 나온다. 분석 기록 목록에서도 확률 예측을 열 수 있다. 모의매매 분석은 별도 기록이며 종목과 발행 회차에 맞는 출처를 표시한다. 조회 목적과 메뉴 구성은 [제품 기획](../../PRODUCT.md)과 [화면 설계](../../DESIGN.md)에 기록한다.
